КАК РАБОТАЕТ WARM-UP АВТОМАТИЗАЦИЯ
===================================

Это не "бот внутри Linken Sphere". Скрипт работает на уровне ОС: смотрит
на экран как человек, двигает курсор и нажимает клавиши через системные
API. Поэтому Linken Sphere его не видит и не отличает от живого юзера.

ЧТО ИСПОЛЬЗУЕТСЯ
----------------

1. Pillow (PIL.ImageGrab)
   Делает скриншоты всего экрана (GDI/DirectX, как Print Screen).
   Возвращает картинку, которую дальше анализирует OpenCV.

2. OpenCV (cv2.matchTemplate)
   Ищет на скриншоте маленькие PNG-картинки из папки templates/
   (кнопка "три точки", "Warm up", "START" и т.д.). Возвращает координаты
   найденного элемента — куда нужно кликнуть. Это называется
   "template matching": алгоритм сравнивает пиксели и находит совпадение.

3. pyautogui
   Двигает мышь и нажимает клавиши через Windows API (SendInput).
   Для ОС это абсолютно неотличимо от живого юзера за компьютером.
   - pyautogui.click(x, y) — клик в точку
   - pyautogui.typewrite("текст") — печать текста
   - pyautogui.hotkey("ctrl", "v") — комбинация клавиш

4. ctypes (Windows API напрямую)
   Для задач, где pyautogui недостаточно:
   - ShellExecuteW — запуск Linken Sphere 2 (как двойной клик в Проводнике,
     нужно для корректной регистрации evo:// протокола Electron)
   - EnumWindows + GetWindowTextW — поиск окна "Authentication" по заголовку,
     чтобы знать где находится форма входа на экране
   - GetWindowRect — координаты окна (для пересчёта позиций полей формы)
   - SetProcessDpiAwarenessContext — без этого на Windows с масштабом != 100%
     скриншоты возвращают физические пиксели, а pyautogui кликает в логических,
     и клики уходят мимо

5. PowerShell Set-Clipboard
   Кладёт пароль в буфер обмена, потом pyautogui делает Ctrl+V.
   Нужно потому что pyautogui.typewrite не умеет печатать спецсимволы
   ('@', '!' и т.п.) через раскладки.

6. taskkill / schtasks
   Системные утилиты Windows:
   - taskkill завершает старые процессы Linken Sphere перед перезапуском
     (нужно если Electron повис со старой сессией)
   - schtasks регистрирует задачу в Планировщике для запуска раз в час

КАК ВСЁ СОБИРАЕТСЯ ВМЕСТЕ
-------------------------

1. Скрипт стартует -> делает скриншот -> ищет в нём шаблон three_dots.png
2. Не находит -> значит надо запустить Linken Sphere ->
   убивает старые процессы taskkill, запускает через ShellExecuteW,
   ждёт 15 секунд пока Electron поднимется
3. Снова делает скриншот. Если видит three_dots — мы на главном экране.
   Если находит окно с заголовком "Authentication" — нужна авторизация.
4. Если авторизация: получает координаты окна через GetWindowRect,
   считает позиции полей Email/Password/SIGN IN как пропорции от высоты
   окна (43% / 52% / 68%), кликает в них, вставляет логин/пароль
   через буфер обмена, нажимает SIGN IN.
5. Дальше — стандартный сценарий: ищет шаблоны кнопок и кликает их.

ПОЧЕМУ ИМЕННО ТАК
-----------------

Альтернативой было бы:
- Использовать API Linken Sphere -> у Warm-up функции его нет
- Парсить DOM Electron -> требует отладочный порт, который пользователь
  не контролирует, плюс детектится анти-фродом
- Selenium/Playwright -> Linken Sphere не браузер, не подключиться

Template matching + системные клики это самый "тупой" но самый
устойчивый способ. Если Linken Sphere поменяет дизайн — нужно будет
пересохранить PNG-шаблоны, и всё снова заработает.

ФАЙЛЫ ПРОЕКТА
-------------

warmup.py                 — сам скрипт
config.ini                — настройки (пути, viewing_depth, time_per_url)
credentials.ini           — email/password (не коммитится в git)
credentials.ini.example   — шаблон credentials.ini
templates/*.png           — картинки UI-элементов для поиска
requirements.txt          — список Python зависимостей
install.bat               — установщик (ставит зависимости, создаёт credentials.ini)
run.bat                   — однократный запуск
schedule_hourly.bat       — регистрация в Планировщике задач (раз в час)
warmup.log                — лог работы
screenshots/              — скриншоты каждого шага (для отладки)
